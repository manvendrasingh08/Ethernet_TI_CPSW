---
Linux uses a single softirq (NET_RX_SOFTIRQ) to drive all NAPI polling, as both RX and TX needs polling, for tx it is completion handling and for rx it is 
packet processing which needs polling so it raises NET_RX_SOFTIRQ

net_rx_action() is the central NAPI scheduler that is called when NET_RX_SOFTIRQ is raised in a deferred context instead of hard IRQs
	What it does:
		Iterates over the per-CPU NAPI poll list
		Calls napi_poll() for each scheduled NAPI instance
		Once all NAPI instances are processed or budgets are exhausted, it returns.
		
napi_poll() : 
Each call to napi_poll() is passed a budget.
what is budget? Its how many RX packets or TX completions are processed per poll cycle
why it exists?  Prevent softirq from dominating the cpu and avoid user and other task starvation. For BBB its 300

invokes each registered NAPI poll function.
 

## 🔹 `net_rx_action()`

`net_rx_action()` is the softirq handler executed when `NET_RX_SOFTIRQ` is raised.
Its main role is to process all scheduled NAPI instances in a deferred context instead of hard IRQs.
It iterates over the per-CPU poll list and i
These poll functions handle **both RX packet reception and TX completion cleanup**.
It enforces polling budgets to prevent CPU starvation and ensures fairness across devices.


---

## 🔹 `napi_poll()`

`napi_poll()` is the generic function that invokes a driver’s NAPI poll callback.
It passes a budget value that limits how many packets or completions can be processed in one run.
The driver poll function processes RX packets and TX completions up to this budget.
If all work is completed, NAPI polling is disabled and interrupts are re-enabled for the device.
If work remains, NAPI stays scheduled and polling continues in the next softirq cycle.
This mechanism reduces interrupt load and improves throughput under high traffic.

How skb shells are processed? 
==============================

Now that the data of the packet is released and onlything remians the skb shell. We have to return  this skb shell to the slab aloocator gaian. Now returning them one by one would be very explensive so they are stored in the napi_alloc_cache. 
Now what is napi_alloc_cache?

napi_alloc_cache is a per-CPU fast-path cache used by the Linux networking stack to efficiently free skb shells by storing them in its feild skb_cache which will be then freed in bulk.
Now it has two member fields one is skb_cache that stores the actual skb shells. It is an array of fixed size NAPI_SKB_CACHE_SIZE which is predefined.For BBB it is 64. Next is  skb_count that keeps the count of the present skb shells in the array.

Now before freeing two things are done : 
 			First the prefetchw(skb) is called. What is this ? As we are abput to write into the skbuff present in cache during the bulk free, it changes the state of the cache line to exclusive. which means only current cpu will be modifying the cache line and no other cpu. It is beneficial as it saves time. Let say the cache line was used bu other cpu, the it had to first invalidate the the other cpu line and then change the state, this stalls the overall process and may cause cache miss.
 			
 			second it checks if the skb_count == threshold value(NAPI_SKB_CACHE_SIZE) if not it just increases the skb_count and another skb
 			called from the clist and the process repeats.
			
			if the threshold value is reached, it then calls the bulk free fucntion:
						
						kmem_cache_free_bulk(skbuff_head_cache, NAPI_SKB_CACHE_SIZE, nc->skb_cache);
